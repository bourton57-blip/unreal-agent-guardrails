## How to read this report

This report deliberately does **not** record a commit SHA. A document that is
itself part of the commit cannot know the SHA of the commit that contains it:
writing that SHA changes the file, which changes the SHA. Any such value would
also become stale the moment the next commit lands.

The stable facts are recorded instead:

- the release candidate under review;
- the exact file count, verified against the Git tree;
- the checks performed and their results;
- the two-layer scanning model, and what each layer is responsible for.

The authoritative commit SHA, the tag target and the CI run for the published
tree are verified directly against the repository by QG, not copied from here.

## 2. Two-layer scanning model

The repository ships a **generic** scanner only. Project-specific checking is
performed separately and never committed.

| Layer | Location | Responsibility | Shipped? |
|---|---|---|---|
| Public | `tests/Invoke-LeakScan.ps1` | Universal hygiene: secrets, credentials, personal paths, sensitive files, engine asset extensions, file size | **Yes** |
| Private | QG internal, outside the repository | Confines the private project identifiers that must never escape | **No** |

The public scanner contains no project-specific identifier and no knowledge of
any private codebase. Its rules apply unchanged to any repository.

The private scanner is not part of this repository, is not committed, and is
not described here beyond this sentence. Recording its contents here would
publish exactly what it exists to contain.

### Why this split exists

An earlier revision embedded the private identifier list directly in
`tests/Invoke-LeakScan.ps1`. That was a genuine defect: publishing the
repository would have published the very identifiers the scan was meant to
protect. The list now lives only in the private QG layer, and the public
scanner was rewritten from scratch around universal rules.

A second, smaller problem is also fixed. The public scanner excludes itself
from its own scan, because a scanner necessarily contains the strings it
searches for. Both exclusions it applies are declared in the script itself
rather than left implicit.

## 4. Fixtures and examples

All fixtures and examples are synthetic and were authored for this project.
None derives from a private codebase, and no engine content, marketplace asset
or plugin binary is present.

The single binary fixture is not an executable. It is a generated byte array of
ASCII text, present so the digest logic has real bytes to hash. It is committed
with a `.gitattributes` rule marking it `-text`, because an end-of-line
conversion would change its bytes and break the pinned checksum. That was a
real defect caught by CI and not by a local run.

Two fixtures are intentionally invalid, to prove the tool rejects bad input: a
malformed manifest, and a governance index declaring a status outside the
model. Both are asserted by the test suite.

## 7. Items requiring human decision before publication

1. **Visibility.** The repository is private and must stay private until QG
   explicitly authorises publication.
2. **Schema identifiers.** `schemas/*.json` use a reserved non-resolving domain
   as the JSON Schema `id`. Safe as-is; replace with the final public URL.
3. **Motivation wording.** The README states the methods arose from practice on
   a real Unreal Engine game project. Confirm the wording remains acceptable,
   given that project is never named.
4. **Security contact.** Enable GitHub Private Vulnerability Reporting on the
   repository after publication.
5. **CI scope.** Only Windows is claimed and tested. macOS and Linux are
   unverified and documented as limitations. Do not add them to the matrix
   without testing.
6. **Dependency deprecation.** `actions/checkout@v4` emits a Node.js 20
   deprecation warning. It is a warning, not a failure; upgrading is a
   maintenance item, not a blocker.

## 8. Verdict

The public tree contains no project-specific identifier in any file, including
the shipped scanner. Generic hygiene checks pass, the private confinement scan
passes, the test suite passes, and every file is accounted for.

Publication is not blocked by this audit. Item 1 in section 7 is a QG decision
rather than a defect.
